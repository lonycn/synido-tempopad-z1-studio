# v2 映射与协议核查

> 输入映射仍适用。以下灯光部分是v2.0历史记录；v2.1已增加经独立核查的RGB输出，当前依据见 [PROTOCOL_V21.md](PROTOCOL_V21.md)。

证据：官方说明书 PDF，及本机 `/Applications/Synido TempoPADZ-1.app` 1.2.0 / build 7 的只读静态分析。未向设备发送命令。

## 坐标

以下 r=0…7 从下到上，c=0…7 从左到右。

- 物理 PAD 编号：`P = 8*r+c+1`。
- DRUM / USER：`note = 36+4*r+(c%4)+32*(c/4)`，整数除法。
- 上排 DRUM：`64 65 66 67 | 96 97 98 99`。
- 下排 DRUM：`36 37 38 39 | 68 69 70 71`。

DRUM 为 CH1；USER 为 CH3。说明书印刷 pp5–6 / PDF 第5页，DRUM 64 格还与官方 `MCustomUIDefaultData.plist` 逐格相符。

## KEY

说明书印刷 p8 / PDF 第6页。每两排基音 `B=36+12*(r/2)`：

- 下排：`B + [0,2,4,5,7,9,11,12]`
- 上排：`B + [停用,1,3,停用,6,8,10,停用]`

52 个有效实体位置、49 个不同音高（36–84），48/60/72 各重复两次。CH1，默认八度与移调为零。重复音无法从音符消息唯一反推实体位置，界面显示全部匹配格。

## EASY 输入：静态观察，不是公开协议

官方程序的三字节输入路径：

```text
i = note(DRUM)-36
按下：F0 i F7          (i=0…63)
松开：F0 (i+64) F7
```

无独立力度字节，助手使用力度 100。解析器仅被动接收，支持 packet 拆分、实时字节穿插，按端点保留状态；不向设备发送握手、切换模式或其他 SysEx。

静态证据（arm64 地址）：

- `MEasyMainViewController.viewDidLoad`，`0x10002d80c`：注册 F0、长度3。
- callback，`0x10002dac4`：第二字节 ≤63 为按下，>63 为松开。
- `DevicePadTanformCollectionIndexWithDevicePad:`，`0x10000d1f8`：四分区转网格。

这是强静态证据，**不等于已完成实机协议验收**。若硬件 EASY 不直接产生该输入，助手 EASY 可用 DRUM/CH1 或 USER/CH3 标准 MIDI 做备用；不通过发送猜测的初始化消息解决。

## 灯光

说明书印刷 p9 / PDF 第7页，只公开 USER/CH3 的 MIDI Note 反馈：音符决定位置，力度决定127色之一。没有明确给出 RGB 对照表及熄灭语义；USER 输入固定满力度。

未发现公开的 EASY RGB SysEx 协议。官方二进制虽含私有输出路径，**v2.0不实现、不发送**。DRUM/KEY 保持设备原有灯光；EASY 界面动画是屏幕反馈，不能声称实体扩散已受控。

后续若需要实体灯光，应作为独立功能，先确认协议与退出时恢复／熄灭策略，再取得用户对实际设备测试的确认。
