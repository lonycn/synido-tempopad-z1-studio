# v2 分析、独立审查与验收边界

本轮先规划，再由两个只读子任务分别核查设备映射／协议和UI／架构；实现后另做一次独立源码审查。实际源码整合由主线完成，避免多个写入者冲突。

## 已采纳

- 不能把DRUM音符顺序直接当屏幕行列：用官方图示和默认资源核对64个位置。
- KEY52位置只有49音高：重复C同时显示，停用位置不可点击。
- EASY从原始未加密WAV独立播放，不破解EAS，不依赖官方软件运行。
- 音频资源放入应用签名前打包；解码预加载，演奏不读磁盘。
- 音频与MIDI处理进入独立串行队列，按端点隔离解析状态。
- 拔插只增删端点；断开时Panic，避免延音踏板残留。
- 鼠标／硬件／试听／无障碍激活使用独立owner，防止延迟释放截断后来按下的音。
- 无障碍激活曾与鼠标共用owner，独立审查发现后改为UUID脉冲owner。
- 初始固定900点高窗口可能超出笔记本可用高度，改为根据visibleFrame等比缩放。
- 32声部多重叠加需要峰值限制，加入Apple PeakLimiter并离线检查。

## 已执行

- Swift编译、ad-hoc签名及严格签名验证。
- 模型测试：64格DRUM与PAD、KEY布局、解析隔离与拆包。
- 离线：DRUM64、EASY64、钢琴、共享所有权、断开清音、64组专用输入及32声部峰值。
- GUI：DRUM64、KEY52有效格、EASY64；三模式切换、音源就绪，官方软件未启动。
- 在新界面观察到真实Z-1标准音符输入与次数／力度更新。没有将此扩张为全64格逐一实机验收。

## 未完成，必须如实保留

- EASY三字节输入语义来自官方程序静态分析；自动测试证明代码按该推断转换，但不能独立证明真实硬件字节排序。应实测PAD5、PAD9、PAD33等区分位置。
- 原厂EASY是否无需初始化即可发出该输入，仍需用户敲击确认。DRUM标准输入作为备用。
- 实体RGB未实现；不发送未知私有SysEx，屏幕动画不能当成实体灯光效果。
- 未测完整延迟、输出设备热切换／睡眠恢复、极端通知风暴、所有屏幕尺寸和VoiceOver流程。
- 视图更新目前逐事件派发，高频合成输入下可进一步合并到固定刷新节奏。
- 保留WAV后段有超高音高合成标签，不是合法MIDI编码；未改动其波形，后续单独听感审查。
